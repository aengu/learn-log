# Practice 앱

연습문제 출제·채점·간격 반복과 러닝메이트 풀이를 담당한다.
학습 로그는 `search.LearningLog`를 FK로 참조하며, 스트릭·통계·일일 학습일지는
`search`에서 `practice`의 풀이 기록을 조회한다.

- URL namespace: `practice` (기존 `/exercises/`, `/api/exercises/` 주소 유지)
- 템플릿: `practice/templates/practice/`
- 테스트: `docker compose exec web pytest practice/tests`
- 커버리지: `docker compose exec web pytest --cov=search --cov=practice --cov-branch`

## 기존 데이터 이전

`search.0011`과 `practice.0001`은 `SeparateDatabaseAndState`로 Django 모델 상태만
옮긴다. 기존 `search_exercise`, `search_exerciseattempt`, `search_mateattempt`
테이블명·PK·FK·인덱스는 유지한다. `practice.0001`은 기존 content type의 앱 이름만
수정하므로 권한·그룹·관리자 이력에서 참조하는 content type PK도 유지된다.

배포 시 평소처럼 `python manage.py migrate`를 실행한다. 새 DB에서는 기존 search
마이그레이션이 먼저 테이블을 만들고, 이후 practice 소속으로 이동한다.
`--fake`나 데이터 복사·테이블 재생성은 필요하지 않다.

## 출제와 개념 태깅

- 새 `path_trace`는 개념 구분·상황 적용·실행 추적 중 자료에 맞는 사고 유형으로 출제한다.
- step마다 `concept_id` 또는 `concept_candidate`, `cognitive_type`,
  `estimated_difficulty`를 저장한다. 기존 문제 JSON은 변경하지 않는다.
- `Concept`은 관리자가 검토해 등록하는 사전이다. 관련 등록 개념을 최대 10개 전달하며,
  사전에 없는 개념은 문항 JSON의 `concept_candidate`에 이름·설명을 남긴다.
  후보는 자동으로 정식 개념이나 숙련도 계산 대상으로 등록되지 않는다.
- 관리자에서 후보와 기존 사전을 검토해 개념을 등록하고, 필요한 기존 문항의
  `concept_id` 연결도 검토한다. 이름만으로 자동 병합하지 않는다.
- 난이도는 출제 시 추정치이며 아직 경험적 난이도나 BKT 파라미터로 사용하지 않는다.
- 자료는 Markdown을 우선 사용하고, 없으면 원문 답변을 사용한다. 6,000자 이하는
  전체 전달하며 긴 자료는 섹션 단위로 선택한다. 조건·예외 섹션을 우선하고,
  섹션 안의 설명·코드·후속 조건을 함께 보존한다. 과대 섹션은 통째로 제외하고,
  닫히지 않은 코드나 선택 가능한 섹션이 없는 자료는 출제 실패로 처리한다.
- 참고 자료 섹션은 제거하고 공식문서 URL 하나만 출처로 덧붙인다. 등록된 공식 출처나
  기존 공식문서 도메인 목록을 기준으로 판단하며, Markdown 참고 자료의 첫 공식문서를
  우선한다. 본문에 없으면 연결된 공식 출처 중 등록 순서로 선택한다. 공식문서가 없으면
  링크를 생략한다. URL 본문을 가져오는 추가 네트워크 요청은 하지 않는다.
- `_generation`에 프롬프트 버전·입력 길이·생략 섹션 수·제공 개념 ID를 기록한다.
- `correct_answer`는 인덱스 일치 검사를 위해 유지한다. 형식·태그 검증은
  기술적 사실성이나 정답 유일성을 보증하지 않는다. 해당 품질은 실제 문항으로 검토한다.
- 러닝메이트에는 기존과 같이 질문·보기만 전달하며 태그·정답·오답 해설은 제외한다.

풀이 시간 수집·망각 확장은 후속 단계다.

## 문항별 개념 검토 상태

수동 검토한 step은 `_concept_review`에 `status`, `reason`, `reviewed_at`,
`original_candidate`를 보관한다. `approved`는 등록 개념에 연결한 문항이며,
`on_hold`는 정답·조건·해설·표시 등의 보정이 필요한 문항이다. 검토 정보가 없으면
미검토 상태다. 정상 문항은 `concept_id`를 연결하고 `concept_candidate`를 비우되,
원래 후보는 검토 이력에 남긴다. 보류 문항은 후보와 원본 내용을 유지한다.

`approved`이고 활성 개념 ID에 연결된 문항만 BKT 관측 대상으로 선택한다.
보류·미검토·미등록 후보 문항은 제외한다. 기존 질문·정답·풀이 점수는 이 검토로
소급 변경하지 않는다. 검토·개념 등록·승인/보류 자체는 아직 수동 작업이다.

## 기본 BKT — 단일 사용자 MVP

`ConceptMastery`는 개념별 숙련도·관측 수·정답 수를,
`BKTObservation`은 문항별 정오답·관측 전 정답 예측·베이즈 사후 확률·학습 전이 후
숙련도와 원문 스냅샷을 기록한다. 관리자에서는 읽기 전용으로 확인한다.

- 기본값: 초기 숙련도 0.3, 실수율 0.1, 추측 정답률 0.25, 학습률 0.1.
  데이터로 학습한 값이 아니라 4지선다를 참고한 가정값이다. 난이도·시간·망각은 미반영.
- 숙련도와 정답 확률은 다르다. 예측 정답 확률은 `L * (1-slip) + (1-L) * guess`다.
- 정오답으로 베이즈 사후 확률을 구한 뒤 `posterior + (1-posterior) * learn`으로 갱신한다.
  오답 뒤에도 학습 전이가 더해지므로 모든 오답이 최종 숙련도 하락을 뜻하지는 않는다.
- 새 풀이 저장·복습 주기 갱신·BKT 기록은 같은 트랜잭션에서 처리한다.
  정상 UI는 응답 후에만 다음 단계로 진행한다. BKT의 추가 형식 검사는 누락·범위 밖
  인덱스·문자열·bool 등 비정상 선택값을 오답으로 집계하지 않기 위한 서버 측 방어다.
- `(attempt, step_index)` 유일 제약과 개념 행 잠금으로 같은 관측의 중복 반영을 막는다.
  별도의 새 풀이 시도는 별도 관측이며, 동일 문제 반복의 학습 효과는 아직 구분하지 않는다.
- 단일 사용자용이다. 러닝메이트 풀이와 자가 채점은 반영하지 않는다.

수동 승인 후 과거 풀이를 반영하거나, 승인 철회·개념 재분류·풀이 삭제·파라미터 변경이
있으면 시간순 재구성이 필요하다. 아래 명령은 검토·승인을 대신하지 않는다.

```bash
# 기본은 DB 저장 없는 미리보기
docker compose exec web python manage.py rebuild_bkt

# 현재 검토 상태로 BKT 결과 두 테이블만 재구성. 원본 문제·풀이·점수는 보존
docker compose exec web python manage.py rebuild_bkt --apply
```

이미 관측한 문항의 본문·보기·정답이 변경됐다면 재구성을 중단한다. 기존 문항과 풀이를
보존하고 원문은 보류한 뒤 수정본을 새 문제로 생성한다. 첫 반영 전에는 원문 스냅샷이
없으므로, 과거 풀이를 수동 승인할 때도 해당 풀이 이후 원문이 바뀌지 않았는지 확인한다.
관측이 없는 개념은 상태 행이 없으며 0% 숙련도로 취급하지 않는다. 현재 상태와 이력은
초기 가정 기반 추정치일 뿐, 충분히 검증된 숙련도나 망각·실수 원인 진단은 아니다.

## 러닝메이트 BKT 수준 보정

- 승인·활성 개념에 연결된 정상 4지선다 문항은 사용자 BKT로 정답 확률을 정한다.
  `L * (1-slip) + (1-L) * guess`를 사용하며, LLM 정답 확률과 다시 혼합하지 않는다.
- 문제 페이지에서 `MateAttempt`가 생성된 시점보다 앞선 마지막 개념 관측의
  `mastery_after`를 사용한다. 과거 관측이 없으면 초기 숙련도 0.3(정답 확률 44.5%)을 쓴다.
  같은 세트의 문항들은 같은 사전 상태를 사용하며 가상의 학습 전이를 추가하지 않는다.
- 미검토·보류·미등록·비활성 개념 문항은 기존 최근/유사 풀이 기반 추정과
  LLM 판단의 80:20 혼합을 유지한다. 이때도 생성 시점 이전 사용자 풀이만 사용한다.
  과거 BKT 관측의 모델 버전/파라미터가 현재와 다르면 기존 추정으로 대체하고 이유를 남긴다.
- LLM에는 질문·보기만 전달한다. 서버는 정답 확률을 보정하고 오답 간 비율은
  LLM 판단을 유지해 샘플링한다. 러닝메이트 풀이가 사용자 BKT를 갱신하지는 않는다.
- `context_snapshot`의 `step_abilities`에 문항별 출처·숙련도·정답 확률·관측 ID·
  파라미터를, `ability_cutoff`에 기준 시각을 남긴다. 기존 풀이 결과는 변경하지 않는다.
- 별도 러닝메이트 숙련도·파라미터 학습·풀이 설명 생성은 아직 추가하지 않는다.
  생성 시점으로 관측을 제한하지만, 이후 수동 검토/재구성된 과거 이력까지 고정하는
  불변 스냅샷은 아니다. 시점 당시의 검토 상태를 완전히 재현하는 기능은 별도 과제다.

## 숙련도 표시와 통계 그래프

- 선택지 문제 제출 결과의 접힌 ‘숙련도 변화’에서 저장된 문항별 관측을 표시한다.
  풀이 전 → 정오답 반영 직후 → 학습 전이 후 숙련도와 풀이 전 예상 정답률,
  당시 파라미터를 확인할 수 있다. 반영 관측이 없으면 ‘BKT 미반영’으로 표시한다.
- `/stats/`에서 등록 개념별 현재 숙련도·예상 정답률·반영 문항 수를 표시한다.
  기록 없는 개념은 0%가 아닌 ‘관측 없음’이다. 예측은 상태에 저장된 파라미터로 계산한다.
- 개념을 선택하면 문항 반영 순서대로 초기값과 풀이 후 숙련도를 SVG로 연결한다.
  점 또는 전체 이력의 순서를 선택하면 해당 관측과 당시 파라미터를 확인한다.
  추가 차트 라이브러리·LLM 호출 없이 서버에서 읽기 전용으로 렌더링한다.
- 시간에 따른 망각 곡선이 아니며, 파라미터 변경 후 재구성하면 과거 곡선도 바뀐다.
  현재 개념 사전은 평면 구조이고 상위 개념 집계나 망각·실수 원인 진단은 제공하지 않는다.
